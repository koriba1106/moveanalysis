# ムーブ解析by武庫 — Move Analysis by Muko

クライミング／ボルダリング動画から、身体座標系を使ってヒールフック、トゥーフック、ドロップニー、クロス、フラッギング、対角姿勢などを検出するブラウザアプリです。

## このWeb版の設計方針

Python版 v2.1 の判定思想をできるだけ維持しながら、ブラウザ向けに以下を再設計しています。

- MediaPipe Pose Landmarker による姿勢推定
- 腰の中点を原点とする体幹相対座標系
- EMA平滑化
- ムーブの時間ベース安定化
- 四肢の停止点検出と近接点マージ
- v2.1 と同じ判定しきい値群・優先順位を基本維持
- MP4をブラウザ内でエンコード
- 出力後にMP4を再読込し、期間・フレーム数・解像度・動画トラックを検証
- キャンセル／例外時は未完成ファイルを成果物として扱わない
- 動画そのものはサーバーへアップロードしないローカル処理

MediaPipe Tasks Vision のWeb版は入力データを端末内で処理します。ただしMediaPipeの利用状況・性能に関するメトリクス送信について公式の説明があるため、完全な「ネットワーク通信ゼロ」を意味するものではありません。モデルとWASMをCDNから取得する構成も含め、公開時にはプライバシー表示を確認してください。

## 技術構成

- TypeScript
- Vite
- `@mediapipe/tasks-vision` 1.0.1
- `mediabunny` 1.61.0
- WebCodecs対応ブラウザを利用したMP4エンコード

Mediabunnyはブラウザ上でMP4を読み書きでき、CanvasSourceからフレームを追加できます。旧 `mp4-muxer` は現在deprecatedでMediabunnyへの移行が案内されているため採用していません。

## 出力の堅牢化

Python版で問題になった「数秒しか保存されないのに処理成功扱いになる」問題をWeb版では次の考え方で防ぎます。

1. 出力フレームを1枚ずつエンコーダへ投入
2. 生成したフレーム数を内部カウンタで記録
3. 出力MP4をBlobとして完成させるまでダウンロードリンクを作らない
4. 完成後にMediabunnyで再読込
5. 動画トラックの存在を確認
6. 出力期間と生成フレーム数／FPSから計算した期待期間を比較
7. 解像度を比較
8. フレーム投入数と検証対象フレーム数を一致確認
9. いずれかに失敗したら出力を成功扱いにしない
10. キャンセル時は完成MP4を公開しない

なお、ブラウザ版ではPython/OpenCVの `VideoCapture` のような「入力ファイルの実フレーム列を直接読みながら書く」方式ではなく、HTMLVideoElementをフレーム時刻へシークして解析する方式を採用しています。そのため、VFRや特殊なコーデックでは完全なフレーム同一性が保証されるわけではありません。今後の第2段階ではMediabunnyの動画サンプルデコーダを解析ループにも使うことで、この差をさらに縮められます。

## 重要な互換性上の注意

WebCodecsの `VideoEncoder` は主要ブラウザのすべてで同一条件の対応が保証されているAPIではありません。対応状況はブラウザ・OS・ハードウェアに依存します。そのためアプリはエンコード／検証失敗を成功扱いしません。
